Quick Reference 02

TypeScript Core

型は、実行前にコードの使い方を検査するための情報。実行時の値と、コンパイル時の型を分けて追う。

よく使う構文

オブジェクト型・関数

type User = {
  id: number;
  name: string;
  email?: string;
};

function label(user: User): string {
  return `${user.id}: ${user.name}`;
}

ユニオン・絞り込み

type Result =
  | { ok: true; value: string }
  | { ok: false; error: Error };

function message(result: Result) {
  if (result.ok) {
    return result.value;
  }
  return result.error.message;
}

仕組み：型検査から実行まで

  1. コードを解析
  2. 型を推論
  3. 型の整合を検査
  4. JavaScriptを出力
  5. 実行環境で動作
二つの世界: type や interface は主に型検査で使われ、通常は出力 JavaScript に残らない。typeof、条件分岐、判別用プロパティなどを使うと、制御フローに沿って広い型を安全に絞り込める。

ありがちな誤解

  • 型が通れば実行時も安全？ 外部入力は型注釈だけでは検証されない。実行時のチェックが別に必要。
  • any は「どんな型でも安全」？ 型検査を避ける値。未知の入力には、絞り込みを要求する unknown が適する。
  • as は値を変換する？ 多くの場合、コンパイラへの型の主張であり、実行時の値を変換しない。

自己テスト

  1. email?: string を読む前に何を確認すべきか。実行時の値も含めて説明する。
  2. 上の Result で result.ok を調べると、なぜ value を読めるのか説明する。
  3. JSON.parse の結果へ型を付けただけでは不十分な理由と、必要な実行時検証を挙げる。
