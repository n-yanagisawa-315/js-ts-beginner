Quick Reference 03

Node.js Core

Node.js は JavaScript をブラウザー外で動かす実行環境。入口、入出力、非同期の完了、終了条件を順に追う。

よく使う構文

CLI・ファイル

import { readFile } from "node:fs/promises";

const path = process.argv[2];

try {
  const text = await readFile(path, "utf8");
  console.log(text);
} catch (error) {
  console.error(error);
  process.exitCode = 1;
}

HTTP サーバー

import { createServer } from "node:http";

const server = createServer((request, response) => {
  response.writeHead(200, {
    "content-type": "application/json"
  });
  response.end(JSON.stringify({ ok: true }));
});

server.listen(3000);

仕組み：非同期 I/O の実行順

  1. スクリプト開始
  2. I/Oを依頼
  3. 他の処理へ進む
  4. 完了を通知
  5. 後続処理を実行
イベントループ: JavaScript のコールスタックが空くと、準備のできたコールバックなどが実行される。await はプロセス全体を止める命令ではなく、その async 関数の続きが Promise の決着後に再開される境界。

ありがちな誤解

  • Node.js にブラウザー API は全部ある？ 実行環境が違う。DOM の document などは通常存在しない。
  • readFile は呼んだ行で完了する？ Promise 版は完了を待つ必要がある。await または then で結果を扱う。
  • process.exit() は安全な終了方法？ 保留中の出力を打ち切る場合がある。通常は process.exitCode を設定して自然終了させる。

自己テスト

  1. CLI 例を引数なしで実行すると、どこで何が起きるか。入口からエラー処理まで説明する。
  2. await readFile の待機中、プロセス全体が停止するわけではない理由を説明する。
  3. HTTP 例で二つのリクエストが来たとき、共有してはいけないリクエスト固有の値を挙げる。
